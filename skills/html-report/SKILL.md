# html-report

人が読んで判断する文書を、**単一 HTML の解説ページ**にする。読み手が「何を決めればいいか」「なぜその推奨か」を最短で掴めることが目的で、見た目のためではない。

縛りを先に置く: **原本は Markdown のまま残し、HTML は派生物。原本に無い主張を HTML に足さない。** 記述の正は常に原本にある。

## 手順

### 1. 原本から取り出す

原本を読み、次を抜き出す。

- 人に決めてほしいこと
- 選択肢と評価基準
- 推奨とその根拠
- 未確認事項

原本に無い項目は創作しない。選択肢表が作れないなら、空の表を置かず「原本に記載なし」と書くか、その節ごと省く。

### 2. ページの構成

上から順に並べる。

1. brief（1〜2 文: 何の文書で、読んだ人に何をしてほしいか）
2. 結論（箇条。各行に短いラベルを付ける）
3. 人に決めてほしいこと
4. 選択肢 × 評価基準の表（推奨の根拠を表の中で示す）
5. 本文の各節
6. 未確認事項
7. フッター（原本のパスと「記述の正は原本」）

### 3. 部品を選ぶ

次の表から、**内容が必要とするものだけ**を選ぶ。文章で足りる節は文章のまま置く。全部は入れない。

| 部品 | 使いどころ |
|---|---|
| 結論の箇条 | 常に置く |
| 構成図（クリックで責務と根拠を出す） | 登場する構成要素が 4 つ以上あるとき。新規 / 既存は枠線の種類でも区別する |
| 状態遷移シミュレータ | 結果を選んで先へ進む流れ。各段で「誰が決めるか」の表の該当行を強調する |
| 開閉式の失敗モード | 起きうる失敗ごとに検出方法と対処を出す |
| 移行段階 | 段階ごとに「やること」「次に進む条件」を並べる |
| 未確認事項の表 | 常に置く（無ければ「なし」） |

### 4. 技術の縛り

- 単一 HTML。外部依存を持たない（CDN・外部フォント・外部画像を読まない。CSS と JS は同じファイルに書く）
- `prefers-color-scheme` でライト / ダークを切り替える。色は CSS 変数にまとめる
- 幅 400px で横スクロールを出さない。表は `overflow-x:auto` のラッパで包む
- JS が無効でも内容が読める。開閉は `<details>` を優先し、JS は切り替えの補助だけにする
- 色だけで意味を伝えない。状態には文言か記号を併記する

最小の骨組み:

```html
<style>
  :root { --bg:#fff; --fg:#1c2024; --muted:#60646c; --line:#d9d9e0; --accent:#0d74ce; }
  @media (prefers-color-scheme: dark) {
    :root { --bg:#111113; --fg:#edeef0; --muted:#b0b4ba; --line:#3a3f42; --accent:#70b8ff; }
  }
  body { background:var(--bg); color:var(--fg); max-width:48rem; margin:0 auto; padding:0 16px; }
  .tbl { overflow-x:auto; }
</style>

<details>
  <summary>失敗: 〇〇が起きる</summary>
  <p><b>検出:</b> …　<b>対処:</b> …</p>
</details>
```

クリックで詳細を切り替える部品は、各要素に `data-id` を付け、10 行程度の JS で対応するパネルの `hidden` を切り替える。パネルは JS が無くても読める位置に置く。

### 5. 置き場と公開

既定は原本の隣のローカル 1 ファイル `<name>.html`。環境が提供する公開手段があれば、それで公開してよい。無い環境でもローカルのファイルだけで成立する。

### 6. 確認

ブラウザで開いて次を見る。

- 幅 400px で横スクロールが出ない（`scrollWidth <= innerWidth`）
- ダーク配色で読める
- クリックなどの部品操作が動く
- 原本との照合: HTML 側の全主張が原本にある

headless Chrome は約 500px 未満のウィンドウを作れない。400px の確認は、幅 400px の `<iframe srcdoc>` に HTML を入れ、中の `documentElement` の `scrollWidth <= clientWidth` で見る。

## やらないこと

- 原本の代替にする（HTML だけを残して Markdown を捨てる）
- 原本に無い主張・数値・選択肢を足す
- 装飾だけの部品を入れる
- 数値のダッシュボードにする
